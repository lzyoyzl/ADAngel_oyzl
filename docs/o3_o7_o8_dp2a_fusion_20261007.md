# O3/O7/O8：精确整数 dot 重构的前置检查（v115）

本轮先检查指令实现成本和24样本的 scale 范围，不重复已失败的 tile/warp/stage/MMA链候选。
**当前还不是新 GEMM：没有新延迟、加速比、MSE、端到端或 GPU 安全测试结果。正式默认不变。**

## 与旧优化的实质区别

现有 v78/v89 在 high MMA 后乘16，再把 low MMA 加入同一 partial，最后乘本组整数 factor 并累加。
v61/v67 使用分开的 low/high partial，但通过普通整数乘加重构。本次探索一种不同的后处理：

```text
两路原生 INT4 MMA → 两个精确 S16 点积 → 打包 → S16×U8 两项 dot → INT32 accumulator
```

设 `L=sum(low*W)`、`H=sum(high*W)`，G128 下保守范围为：

```text
abs(L) <= 128*15*8 = 15360
abs(H) <= 128*8*8  = 8192
```

两者都能精确表示为 INT16，不是近似截断。若本组整数 factor 为 `f<=15`，则
`[f,16f]` 都能表示为 UINT8。把 L/H 的低16位拼接，并调用 `dp2a.lo.s32.u32`，语义为：

```text
acc += L*f + H*(16*f) = (L+16*H)*f
```

原始量化、G128 scale、两路 INT4 和全K INT32前缀/输出 guard 均须保留。
这是普通 CUDA 整数 dot 后处理，不是将 Tensor Core 改成 INT16，也不是使用 INT8 Tensor Core。
语义来源：[NVIDIA PTX 的 DP2A 定义](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#integer-arithmetic-instructions-dp2a)。

与 v72 的系数提前计算、v87 的系数移位、v96 的 N64 边界调度和 v98/v104 的八warp几何均不同。
不过，**PTX 支持不代表 SM80 一定有一条对应的原生机器指令**；必须先看 SASS，不能重复5090 INT4语义展开的误判。

## 先做什么检查

1. 复用带原始SHA的全24样本快照，不重新量化或选取有利样本。
   O3 的正常UE8M0码满足 `max-min<=3` 时，最大factor为8，满足上述范围。
   O7/O8仅观察A factor，W factor尚未检查，因此只能给出**假定W factor>=1的条件性覆盖上界**，不能冒充完整可用率。
2. 只编译两项 dot 的最小成本探针，不启动任何 GPU kernel，不做小样本性能初筛。
   候选必须落为一条 S16×U8 dot；若展开为两条 byte dot 或额外重构，停止此方向。
3. 只有O3范围覆盖至少50%、ISA gate也通过，才值得实现完整候选。届时还需重新检查
   原生双INT4、32 partial、64 accumulator、CTA/pipeline、寄存器、热local和全部guard，再直接做24样本配对。

预打包 `[f,16f]` 的费用在完整实现中不能免费忽略：必须计入相应权重准备，Cold统计，steady-state缓存。
本探针仅核对最好情况下的标量指令成本，不能据此声称完整kernel缩短了依赖链或取得加速。
