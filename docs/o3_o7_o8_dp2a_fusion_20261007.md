# O3/O7/O8：精确整数 dot 重构的前置检查（v115）

本轮先检查指令实现成本和24样本的 scale 范围，不重复已失败的 tile/warp/stage/MMA链候选。
**已实现独立 O3 GEMM 候选，但 A100 完整编译门槛未通过，停止此方向。**
未启动候选 GPU kernel，没有新延迟、加速比、MSE、端到端或 GPU 安全测试结果。正式默认不变。

## 与旧优化的实质区别

现有 v78/v89 在 high MMA 后乘16，再把 low MMA 加入同一 partial，最后乘本组整数 factor 并累加。
v61/v67 使用分开的 low/high partial，但通过普通整数乘加重构。本次探索一种不同的后处理：

```text
两路原生 INT4 MMA → 两个精确 S16 点积 → 打包 → S16×U8 两项 dot → INT32 accumulator
```

设 `L=sum(low*W)`、`H=sum(high*W)`，G128 下保守范围为：

```text
abs(L) <= 128*15*8 = 15360
abs(H) <= 128*8*8  = 8192
```

两者都能精确表示为 INT16，不是近似截断。若本组整数 factor 为 `f<=15`，则
`[f,16f]` 都能表示为 UINT8。把 L/H 的低16位拼接，并调用 `dp2a.lo.s32.u32`，语义为：

```text
acc += L*f + H*(16*f) = (L+16*H)*f
```

原始量化、G128 scale、两路 INT4 和全K INT32前缀/输出 guard 均须保留。
这是普通 CUDA 整数 dot 后处理，不是将 Tensor Core 改成 INT16，也不是使用 INT8 Tensor Core。
语义来源：[NVIDIA PTX 的 DP2A 定义](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#integer-arithmetic-instructions-dp2a)。

与 v72 的系数提前计算、v87 的系数移位、v96 的 N64 边界调度和 v98/v104 的八warp几何均不同。
不过，**PTX 支持不代表 SM80 一定有一条对应的原生机器指令**；必须先看 SASS，不能重复5090 INT4语义展开的误判。

## 先做什么检查

1. 复用带原始SHA的全24样本快照，不重新量化或选取有利样本。
   O3 的正常UE8M0码满足 `max-min<=3` 时，最大factor为8，满足上述范围。
   O7/O8仅观察A factor，W factor尚未检查，因此只能给出**假定W factor>=1的条件性覆盖上界**，不能冒充完整可用率。
2. 只编译两项 dot 的最小成本探针，不启动任何 GPU kernel，不做小样本性能初筛。
   候选必须落为一条 S16×U8 dot；若展开为两条 byte dot 或额外重构，停止此方向。
3. 只有O3范围覆盖至少50%、ISA gate也通过，才值得实现完整候选。届时还需重新检查
   原生双INT4、32 partial、64 accumulator、CTA/pipeline、寄存器、热local和全部guard，再直接做24样本配对。

预打包 `[f,16f]` 的费用在完整实现中不能免费忽略：必须计入相应权重准备，Cold统计，steady-state缓存。
本探针仅核对最好情况下的标量指令成本，不能据此声称完整kernel缩短了依赖链或取得加速。

## 前置结果与完整候选门槛

A100 标量探针确认一条 `IDP.2A.LO.S16.U8`，没有展开。全24样本 O3 平均80.729%的N128
tile满足scale条件；O7/O8的条件性A侧覆盖上界为11.719%/0%，不扩展这两个后端。
上述数字不是性能提升或新 MSE。CPU9项整数代数/符号/边界测试通过。

仅为O3实现一个固定CTA64×128×128/四warp/三stage候选：32个partial槽位用于四组low和四组high链，
各自两次K64 MMA；两者完成后PRMT+DP2A更新原64个最终整数accumulator。
量化/输入/原始factor、M8分组遍历和最终FP32转换均不变。
joined metadata保存完整原33*N，再附packed32*N和每N128的eligibility；不合条件的tile使用原v89整数路径，
原有FP32回退/拒绝仍优先检查。额外metadata pack为单独GPU准备kernel，后续Cold必须计入。

编译gate在运行前固定：寄存器<=168、整数热local不高于v89、MMA64与LDSM16不变、
原生DP2A64、无热I2F、热循环静态指令增长不超过5%，且旧v89控制编码逐位相同。
这是依赖结构候选，不保证静态指令总数更少，也不把源码的两步链当作实测硬件延迟。

## 完整编译结果：停止，不重复扫相邻变体

|A100 静态机器码指标（不是延迟）|当前 O3 v89|v115 DP2A 候选|
|---|---:|---:|
|每线程寄存器|168|168|
|整数 G128 热循环指令|323|340（+5.26%）|
|整数热循环 local-memory 读取 `LDL`|0|3|
|原生 U4×S4 / S4×S4 MMA|32 / 32|32 / 32|
|LDSM|16|16|
|PRMT / S16×U8 DP2A|0 / 0|64 / 64|
|热循环 INT32→FP32 转换|0|0|

单条 DP2A 确实保留到完整 kernel 的 SASS，但分开的 low/high partial、打包和地址活跃范围
使完整循环出现额外 local 读取，指令数也超过事先固定的 +5% 投入门槛。
因此没有继续建立新运行时、启动候选 GEMM 或消耗24样本性能测试。
这说明本候选未达到投入标准，**不等于已经实测它更慢，也不是 DP2A 在所有排布中都无效的证明**。
少量 spill 本身不会自动改变数学结果；这里停止是结合额外工作、scale 覆盖与额度限制的成本判断。

旧 v89 控制入口的 SASS 编码逐位相同；正式扩展前后 SHA 相同。
CPU14项整数/符号/边界、metadata、源契约和门槛测试在本地与A100均通过；不是GPU正确性或MSE验收。
当前最佳仍为 O3 v89、O7/O8 v78+v73（v99 输出微调独立保留）。

本轮也查明“增加warp来减少每线程accumulator”的想法与 v98/v104 已测机制重复，未实现或重跑。
后续不再重测本 DP2A 候选及上述旧机制，除非有改变实际成本的新证据；不通过修改阈值重新晋级。
