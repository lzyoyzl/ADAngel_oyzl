# O3 / O7 / O8：当前最佳的 NCU 复核与定向优化

## 结论

当前最佳仍为 **O3 v89；O7/O8 v78 GEMM + v73 准备**，正式默认不切换。
三者必要 INT4 MMA 工作相同，O7/O8 额外的 G128 激活 factor 路径使整体 GEMM 工作不同。
本次针对真实机器码的 local spill 做一次地址重物化候选，完整 24 样本测试确认负收益，
不采纳、不做 tile/stage 参数扫描。目标尚未达到。

## 2. 为什么相同 MMA 仍有额外瓶颈

安全全 K 整数路径：

```text
O3:    I[m,n] += P[m,n,g] * W_factor[n,g]
O7/8:  I[m,n] += P[m,n,g] * A_factor[m,g] * W_factor[n,g]
```

O3 的 A scale 仅随行变化，最终再乘；O7/O8 的 A factor 还随 G128 变化。
与 group 无关的 base scale 已后移，源格式解码已在 conversion 中完成。
当前最佳 O3/O7 的 MMA/LDSM 数量相同，但 O7 总动态指令约多 19.6%。
O3 的三阶段供数与 O7/O8 的两阶段供数、factor shared 读取和编译调度也不同。
O8 激活 6 bit 当前符号扩展后仍走两路 INT4，不会自动减少 MMA 数量。

当前资源模型采用固定实际指令/访存工作、1410 MHz、理想重叠，四份 capture 的
必要容量下界均由 MMA 给出，约 **0.220347 ms**。
O3 v89 / O7 v78 的 L1TEX 容量下界分别约 0.172251 / 0.182576 ms；
observed DRAM bytes / 规格带宽约 0.062579 / 0.054592 ms。
它们是乐观必要下界，不包含全部依赖/等待，也不是保证可达到的延迟。
不能把较早逐 G128 FP32 kernel 的约 0.282/0.286 ms 模型直接套给当前 full-K binary。
现阶段继续提高 MMA 就绪度、减少供数/地址状态的干扰，比单纯减少 HBM 流量更有针对性。

## 3. v91：只改变 A-copy 地址的存活方式

O7 v89 的热循环包含对 spill 地址状态的 `LDL.64`。
候选保持量化、G128 factor、全 K 安全界、CTA、两阶段、两路原生 INT4、八链、
转换和最终输出不变，仅在 `cp.async.cg` 使用处由 base + offset 构造地址，
避免提前生成的 64-bit 派生地址长时间占用寄存器。
采用公开 PTX `mad.wide.u32`，不是私有 ABI 或机器码修改。
[指令语义：NVIDIA CUDA 12.8 PTX 文档](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#integer-arithmetic-instructions-mad)。

v78/v89 编码完全一致的对照、原生 INT4 和缓存策略审计先于性能测试。
只有热循环 LDL 降低且寄存器不超过 168 时才进入 GPU 正确性及完整 24 样本配对测试；
若编译后无改善就停止该候选，不做小样本性能初筛，不宣称新的性能/MSE 结果。
编译筛选器同时统计 `LDL` 和 `LDL.64` 等后缀形式，不能漏计 spill。

实际编译筛选结果：

|整数热循环|v78 对照|v89 分组|v91 分组 + 地址重物化|
|---|---:|---:|---:|
|静态指令数|383|381|379|
|Local load 指令数|0|2|0|
|静态最大存活 GPR|166|166|163|
|分配寄存器 / 线程|168|168|168|
|原生 U4/S4 + S4/S4 MMA|32+32|32+32|32+32|

v78/v89 对照编码一致审计通过；v91 因此进入完整测试，而不是据静态改善直接宣称加速。
已完成 64 项非默认 stream 数值/模式检查、12 项非法编码/范围检查、
8 项分组/tail 混合回退检查，有限 FP32、语义误差和相对 v67/v78 的逐位一致均通过。
这是小 M/N、完整 K4096 的正确性检查，不是小样本性能初筛或全面 sanitizer 证明。
24 样本、三轮、预热 1000 / 正式 200 / 转换内重复 100 的配对性能测试完成：

|GEMM-only|同轮最佳 v78 median ms|v91 median ms|配对吞吐变化|speedup 95% CI|CV≥3%：旧 / 新|
|---|---:|---:|---:|---|---|
|O7|0.474112|0.480256|−1.28%|[0.987207, 0.988285]|0/72 / 1/72|
|O8|0.475648|0.485888|−1.26%|[0.987207, 0.989339]|2/72 / 1/72|

每样本先对三轮取中位数，再对 24 样本汇总；配对 speedup 是同样本同轮的延迟比，
不能直接用表中两个整体中位延迟相除代替它。区间仅描述这 24 个相关真实样本。
288 条记录全部有限 FP32、payload/metadata 正确、相对 v67/v78 输出逐位一致、MSE 差为 0；
O7 全部 CTA 走整数路径；O8 仅 `layer_24_o_proj` 的 12 个 CTA 保留既有安全回退。
少量高 CV 保留、不筛选，也不为负收益反复重测。

**消除 spill 不足以改善整体 GEMM：最佳 v78 本来就没有整数热循环 spill。**
v91 对 v78 同时包含分组遍历与地址重物化，不能把本轮差值解释成纯地址优化的单因素成本。
寄存器分配仍 168、CTA 容量不变、MMA/LDSM 工作不减；静态指令更少不保证依赖/供数就绪更好。
本轮未另采 v91 NCU，不猜测其具体等待比例。
负收益候选不扩展四模式或 sanitizer，不宣称新 conversion/Cold/steady 收益或全面内存安全证明。
