# O5–O10 对混合低精度计算的启示

本文解释本轮实验能支持什么结论，以及不能据此推断什么。格式和实现见
[分组协议](o5_o10_a100_protocol.md)、[kernel 工作流](mixed_precision_kernel_workflow.md)。
旧报告中的双 INT4 O5/O6 现已改名为 O7/O8。

## 1. 统一的不是原始位模式，而是“整数值 + 有效尺度”

不同浮点格式先规范成：

```text
真实值 ≈ 定点整数 q × 有效尺度 s
Y[m,n] = Σg dot(Aq[m,g], Wq[n,g]) × As[m,g] × Ws[n,g]
```

NVFP4、MXFP8、HiF4、FP6 的前端不同，后端可以共用整数点积结构。
但格式契约必须包括编码、符号、scale 层级/范围、F、舍入和饱和规则，
不能只写“Q4”或“Q8”。

例如 E4M3→Q8 的 F=−2 使整数单位对应原局部数值的 4；
E2M3→Q6 的 F=2 则对应 1/4。若不补偿 scale，整数虽能正确相乘，实数输出仍然错误。
HiF4 内部微指数并入局部值后仍可能有分数，F=0 会新增舍入误差，不能称为无损转码。

## 2. scale 边界决定能合并多大的整数点积

只在 As×Ws 不变的区间内，才可先把整数 partial 合并、最后统一缩放。
本轮两侧都是 G128，所以 K256 pipeline 仍处理两个独立 G128。
更大搬运 tile 不等于更大的数学 scale group。

这也解释了为何无法直接用纯 INT4 峰值预测实际性能：组间还要加载 scale、
重构整数、INT32→FP32 和有序 FP32 累加。与原 O3 相比，本轮激活 scale 也逐组变化。

## 3. 同样的定点结果，可以有不同计算成本

O7/O8 的双 INT4 与 O9/O10 的 Binary 只改变整数点积实现，不应改变定点值或输出。
Binary 与对应双 INT4 逐位相等，是“没有额外计算误差”的验证，
**不是**“转定点没有损失”：相对组内 FP16 基线的 MSE 仍然保留。

双 INT4 中 Q6 被符号扩展到 INT8，仍执行低 U4 和高 S4 两路完整点积。
Binary 则能将激活平面从 8 个减为 6 个，使平面对从 32 个减为 24 个。
后者减少了 25% 的平面对，但实际速度还受 packing、重构、访存和寄存器限制，
不能直接承诺 25% 的延迟下降，也不能据此断言 Binary 比 INT4 快。

## 4. 转换器必须为消费端组织数据

旧 row-major scale 的 NCU 证据中，固定 group、相邻 row 的读取跨距为 128 字节；
两处 scale 加载合计产生 11,010,048 个额外理论 global sectors。
改为 group-major，转换器直接按消费顺序输出，可消除这类非合并访问，
无需增加独立重排。这是理论事务量，不是测得的 DRAM 字节数。

见 [历史 NCU 证据](evidence/a100_mixed_ncu_v2/README.md)、
[group-major 对照](evidence/a100_mixed_group_major_v1/README.md)。
这些文件保留旧命名，O5/O6 应读作现在的 O7/O8。
改善 GEMM 加载不保证转换免费，因此四种计时必须一起报告。

Binary 前端同样把解码、RNE、ballot、scale 输出融合，避免完整 INT8 中间张量。
然而 bitplane packing 和多平面重构有自身成本，不能只用“1 bit 更小”推断更快。

## 5. 本轮结果的适用边界

这里验证的是固定 4096³、24 个相关真实 trace 样本上的算子性能和输出 MSE。
完整数据见 [分组结果](o5_o10_a100_results.md)：本轮双 INT4 相对各自 FP16 基线取得约
1.18× / 1.20× compute-only 配对中位收益，Binary 则明显更慢；这是测量结果，不是格式本身的保证。
它不是完整模型吞吐、端到端生成延迟或下游任务精度，也不证明其他 M/N/K 的优劣相同。
NVFP4-G128、HiF4-G128 和 NV-style FP6 是已确认的实验格式扩展。

普通 CUDA Event 结果与 NCU 重放结果分开保存。共享 GPU 的频率/调度变化可能影响
延迟甚至同样本配对比较；中位数不能消除所有争用偏差。保留原始记录和 CV，
比只发布最快一次或删除不利样本更能说明结果的可信范围。
