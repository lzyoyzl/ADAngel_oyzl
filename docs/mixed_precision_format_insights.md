# 任意精度混合量化的挑战与可验证 insight（阶段稿）

本文提出需要通过 O5/O6 验证的假设，不宣称已完成实验或具有论文首创性。

## 核心观察：计算的最小单元由 scale 边界决定，不只由 payload 位宽决定

若一个归约区间内两侧都可写为 x=q×s，则：

    Y[m,n] = sum_g (sum_{k in g} Aq[m,k] Wq[n,k]) × As[m,g] × Ws[n,g]

整数点积只可在 s 的乘积不变的区间内直接合并。
即使所有 payload 都已经是 INT4/INT8，内部 micro-scale 不同也不能
跨它们先累加整数、最后乘一个 scale。反过来，在前端准确对齐到共同
坐标后，多个原始格式可以共享同一个整数 GEMM 后端。

因此比“支持任意位宽”更具体的实现契约应是：
payload 位宽和符号 + scale 的作用域/数值格式 + 对齐/舍入规则 + 误差预算。
统一接口不能靠忽略某些格式的层级 scale 获得简化。

## O5/O6 的三个困难点

**表示闭合性。** 原 O3 的 E2M1+单组 scale 很容易映射为局部 Q4；
NVFP4 的多级 scale、MXFP8 的更大动态范围和 HiF4 的内部指数可能使
局部映射不再等价。必须证明或量化“对齐到 Q 位”丢失了什么。
仅声明 Q4/Q8/Q6 不能唯一确定小数位 F，也不能唯一确定 MSE。

**元数据可能比 payload 更影响调度。** O3 的 A scale 每行不变；
O5/O6 两侧都逐组变化，增加后处理依赖和寄存器/shared 访问。
单纯估算 INT4峰值会漏掉这部分。待验证假设是：把 scale 的共享范围
显式暴露给转换器和 kernel，比仅按 dtype 选 kernel 更重要。

**精度节约不自动转化为算力节约。** Q6 符号扩展到 INT8 后，
当前两路 INT4 算法仍发出同样两份乘积；减少表示位宽可能减少前端误差
或存储需求，但不会自动缩短 GEMM。这需要指令/数据流层面的证据，
不能用理论 6/8 比例预测加速。

## 可形成的通用策略及所需实证

先把不同格式规约为“组内整数 payload + 有效尺度”，但让转换器保留
显式误差账本。计算后端按最细必要 scale 边界归约，再按共享范围广播
元数据，最后在 tile/pipeline 层面实现复用。

为支持这一结论，最终报告应同时给出：

- 多格式/多位宽的转换误差和 MSE vs O0，而不是只有一种格式。
- 相同整数后端下不同 scale 拓扑的指令、shared 访问和延迟变化。
- 同一格式使用不同 stage/tile 时的资源与性能取舍。
- conversion、compute-only、cold、steady 的完整边界，避免离线成本被隐藏。

已确定的 HiF4-G128 合并微指数后仍可能含分数；当前 F=0 的 Q4 会产生
额外舍入（例如局部 0.25→0）。必须单列这部分误差，不能声称是无损重编码。
用户已批准该语义；不能为降低 MSE 偷换为重新拟合 scale 或更细分组。

当前已落实的工程约束是：格式类型不止由 Q 决定。即便后端都是双 INT4，
源 E4M3→Q8 使用 F=-2，而源 E2M3→Q6 使用 F=2；相应整数单位分别乘 4
和除 4。错误复用 F 或遗漏 scale 补偿可能给出运行正常却数值完全错误的结果。
因此编码/符号/scale 的可验证转换契约应先于性能选型。

## 已获得的局部证据：scale 的布局也是后端接口的一部分

合成 4096³ 的 NCU 诊断发现，O5/O6 双侧 FP32 scale 的 `[row,group]`
存储使相邻 lane 在固定 group 加载时跨 128 字节；O5 的两处 scale 加载
贡献了全部 11,010,048 个额外理论 global sector。
同次 shared wavefront excessive 为零，不能把它误诊为 bank conflict。
见 [性能分析与原始证据](o3_o5_o6_performance_analysis.md#5-ncu-定位双侧-scale-的物理布局)。

这支持一个更具体的设计方向：转换器不只产出正确的整数和 scale 数值，
还应按计算 kernel 的协作加载方式输出 scale 的物理布局。这里可以直接
写成 `[group,row]`，不增加独立重排；但必须同时测 conversion 与端到端，
因为改善消费端不保证生产端免费。这仍是候选验证，不是普适加速保证。

O5/O6 此次 GEMM 的动态 warp 指令数完全一致（131,596,288），与其共用
整数内核相符；原始 Q8/Q6 的位宽差异没有自动变成 MMA 指令节省。
格式差异的主要新增成本应分别在前端转换、有效 scale 和误差预算中核算。
