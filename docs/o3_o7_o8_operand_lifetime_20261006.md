# O3 / O7 / O8：A fragment 活跃范围候选（v94）

## 结论

**候选在 A100 编译筛选阶段停止，最佳不变。** 预期通过缩短寄存器活跃范围，
让 O7/O8 从3 CTA/SM提高到4 CTA/SM；实际仍为168寄存器、3 CTA/SM，
LDSM却增加50%。不投入GPU性能、MSE、NCU或sanitizer，不报告未经测量的加速比。
O3、正式默认和5090均未改动。

## 唯一候选及取舍

保持`64×128×128` CTA、128线程、两阶段34304 B shared、原全局payload/metadata复制、
G128 factor、全K安全界及FP32回退、最终FP32输出和v73准备不变。

原实现同时保留两个M atom的A fragment及32个逻辑partial寄存器。
候选每次处理一个M atom，使用16个逻辑partial槽位、4条源码MMA链；
高/低位和两个K64依次覆盖同一个A fragment。坐标来自CuTe identity tensor，
signed/unsigned视图只是同位宽bitcast，不更改输入或量化。

代价是A片段在两个N64窗口中重复从shared读取。与历史N64 **CTA** 不同，
本轮保留N128输出tile，因此没有增加全局payload复制字节；增加的是shared读取。
测试前固定gate为自然分配寄存器≤128、无整数热循环local访问、原生MMA数量不变，
且LDSM为预期24条。保持原`__launch_bounds__(128,3)`，没有强制寄存器上限。

## 实际编译与资源结果

|指标|v78对照|v94候选|
|---|---:|---:|
|源码同时保留的partial槽位|32|16|
|SASS中已开始未结束的MMA链峰值|8|8|
|整数热循环最大活跃GPR|166|157|
|整个entry分配寄存器/线程|168|168|
|CUDA资源查询：最大CTA/SM|3|3（候选实查）|
|整数热循环静态指令|383|380|
|每G128原生S4/S4 + U4/S4 MMA|32+32|32+32|
|每G128 LDSM|16|24|
|整数热循环LDL/STL|0/0|0/0|
|整个entry stack / spill store / spill load B|0/0/0|8/8/8|

同一候选entry的PTX/SASS原生两路INT4及异步copy审计通过，v78对照编码完全一致。
资源查询只加载CUfunction，未执行候选kernel，不是性能或正确性测试。
整个entry的spill与整数热循环零local不矛盾：回退路径有两条LDL。
静态链峰值只是程序顺序，不是硬件同时在途数；源码槽位也不等于分配寄存器数。

**编译器仍交错到8条链，源码缩短活跃范围没有实现预期的4 CTA容量。**
整数热循环只降低9个活跃GPR，回退循环峰值仍为160；不能简单声称移除回退就能达到128。
少3条静态指令不足以抵消预期额外供数工作，故停止本候选，不扫描寄存器cap或增加warp fence。
这不证明所有低寄存器实现无效，但否定了此具体方案的晋级依据。
