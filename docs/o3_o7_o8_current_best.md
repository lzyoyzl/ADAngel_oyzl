# A100 O3 / O7 / O8：当前最佳结果（v32复核）

## 结论

**当前GEMM最佳候选：O3用54，O7/O8用56。正式默认尚未切换，RTX5090代码不变。**
这里按GEMM性能选择版本，不表示每种转换/端到端模式都逐项最优。

O3保留此前的行A scale后移，再将W scale改为G128-major连续读取。
24真实样本、5轮配对确认：相对上一最佳52吞吐提升**0.43%**，相对原正式O3提升**17.33%**。
输出与上一版逐位一致。收益很小且新增重排有成本，cold没有确认改善。
O7/O8将每G128的FP32 A/W scale接入现有异步搬运流水线。24样本×5轮确认，
相对上一最佳42，GEMM吞吐分别提升**1.73% / 1.60%**，输出逐位不变。
其A scale随G128变化，不能直接套用O3的行scale后移。

共同实现：两路原生INT4、CTA `64×128×128`、4 warp、寄存器partial、G128独立scale、
B fragment跨M复用、G128-major低位输入布局、FP32输出。当前三个最佳候选均使用三阶段
`cp.async`流水线。O3/54保留范围检查；不满足未缩放中间值上界时明确拒绝，不偷偷换算法。

O3沿用v30，O7/O8来自v31；不是三个后端在本轮重新同时测量。
吞吐变化来自同样本、同轮配对，不是用跨运行的median相除。

## 6. 本轮为什么更快，为什么仍有差距

上一轮行scale后移减少了重复scale组合，相对当时最佳提升4.28%。
本轮52→54仅优化W scale读取：NCU的global excessive理论sectors从8,126,464降至0，
动态warp指令99.62M→99.32M，仅少约0.30%；local理论sectors仍3.18M。
IMMA、I2F、FFMA仍各16.78M条，shared wavefront仍29.62M；寄存器168/线程、最多3 CTA/SM。

**scale读取更整齐，但主要计算和等待链路仍在，所以只有约0.43%收益。**
两阶段53虽然零spill，却没有超过旧三阶段52。不能仅根据零spill、访存效率或利用率判断速度。
NCU上述sector是理论访存工作量，不是实际HBM字节；profiling时间也不是正式Event延迟。

当前必要容量下界仍约0.220347ms@1410MHz，受MMA/I2F约束。
它假设理想资源重叠，不是保证可达到的kernel时间；本轮尚未达到该下界。

O7/O8本轮已将scale供数接入cp.async流水线，后处理数学工作量并未减少。
同binary NCU中，O7动态指令反而增加1.04%，但eligible warp从0.737增至0.785，
not-issued long-scoreboard样本占比从14.86%降至6.38%。这与隐藏scale读取等待的解释一致，
不能把样本占比当作耗时比例。IMMA/I2F/FMUL/FFMA仍各16.78M，寄存器及spill未减少。
v32已实测M32/N128 tile：每线程最终accumulator从64降为32，
寄存器168降至128、零spill、可驻留CTA从3增至4，但24样本配对吞吐下降6.4%～7.7%。
同binary NCU显示动态指令增加约20%、LDSM增加50%、shared wavefront增加约47%，
M方向复用损失超过占用率收益。因此仍保留54/56为当前最佳，不以零spill作为优化目标。
接下来只改host有界的地址计算类型，检查是否减少寻址指令；尚无上机收益结论。
定点转换直接生成最终布局也可继续改进，但必须计入全部转换成本。
不盲目增加树形归约窗口，不重启已无收益的magic-bias。
跨G128改用INT32累加属于新的实现约束，尚未实施，需另行确认。

## 验证、限制与证据

v30通过192项GPU合成检查、原生INT4指令审计、20项入口保护检查、
有限memcheck/synccheck/racecheck及mixed格式回归。54有spill，不宣称零spill。
12个旧正式函数、140个旧候选编码SASS不变；另4个非目标mixed-binary函数的codegen变化
已披露并补充回归，不声称整份扩展完全不变。

v31通过384项GPU预检、26项入口保护、144个候选原生INT4审计；
memcheck/synccheck各168项检查、racecheck K768均未报错。56仍有spill。
12个旧正式和142个旧候选编码SASS不变；5个非目标mixed-binary编码变化，
已保留差异并补做mixed回归，不能声称所有函数机器码不变。

共享GPU、未锁频、不删离群：五轮最佳compute的CV≥3%数量，
O3为43/120，O7为63/120，O8为51/120。
O3新版四模式选定阶段的CV≥3%为0/24、8/24、1/24、17/24。
O7为0/24、10/24、3/24、12/24；O8为0/24、9/24、1/24、13/24。
**上述结果不等同于严格全阶段CV<3%验收。**
同一trace中的24样本有关联，bootstrap区间只作描述性比较。

已构建SM80扩展后，分别运行；输出目录必须不存在。普通正式调度不会自动选择这些内部候选。

```bash
# O3：需要明确允许FP32重新结合。

  --variants o3 --output runs/o3_best_recheck \
  --samples 24 --rounds 5 --warmup 50 --repeats 200 --tunes -1 52 54

# O7/O8：保持原来的逐位一致要求。
python scripts/benchmark_a100_roof_trace.py \
  --variants o7 o8 --output runs/o78_best_recheck \
  --samples 24 --rounds 5 --warmup 50 --repeats 200 --tunes -1 42 56
```
