# A100 O3 / O7 / O8：当前最佳结果

## 结论

**GEMM-only当前最佳是O3候选41、O7/O8候选42；正式默认尚未切换，RTX5090代码不变。**
新版本改善低位输入的物理排列，输出与旧实现逐位相同。但独立重排增加转换成本，
不能把GEMM收益直接称为端到端收益。

共同实现仍为两路原生INT4、CTA `64×128×128`、4 warp、寄存器partial、
独立G128 scale和FP32输出；保留B fragment复用。O3采用两阶段、O7/O8采用三阶段
`cp.async`流水线。新布局把同一G128内的相邻行排在一起，不重新量化、不改变求和顺序。

## 1. Compute-only / GEMM-only

v24同binary，24个真实样本×5轮，warmup50/repeats200，五种实现循环换序。
“吞吐提升”按同样本同轮速度比汇总，不必等于表中总体median直接相除。

|后端|旧正式 median ms|上一版最佳 median ms|新最佳|新 median ms|相对上一版最佳吞吐提升|
|---|---:|---:|---:|---:|---:|
|O3|0.569344|22：0.540672|41|0.509952|+6.13%|
|O7|0.608512|23：0.541696|42|0.526592|+2.71%|
|O8|0.610816|23：0.543232|42|0.529408|+2.83%|

上述配对speedup的描述性bootstrap 95%区间分别为
`[1.05625,1.06413]`、`[1.02534,1.03099]`、`[1.02599,1.03101]`。
相对旧正式默认，配对吞吐提升分别为11.75%、15.50%、15.39%。
这不是相对FP16 O0/O5/O6的加速比。

## 2. Conversion-only

四模式使用另一次24样本、1轮配对，warmup50/repeats200、转换inner100。
与上表不是同一轮，禁止跨模式相加median构造总时间。三种后端合计864条四模式记录。

|后端|上一版最佳 total median ms|新候选 total median ms|
|---|---:|---:|
|O3（22→41）|0.098744|0.130145|
|O7（23→42）|0.133847|0.167112|
|O8（23→42）|0.117166|0.151352|

包含源格式→定点/INT4平面转换，以及新候选的额外payload重排。
4096³重排增加A读写32MiB、W读写16MiB，计时和逻辑字节数均计入，没有免费移到离线。

## 3. Cold：全部在线转换加GEMM

直接计时一次完整执行，不用各阶段median相加。

|后端|上一版最佳 median ms|新候选 median ms|配对吞吐变化|
|---|---:|---:|---:|
|O3（22→41）|0.652288|0.650752|−0.24%，无明确变化|
|O7（23→42）|0.699392|0.699904|+0.29%，无明确变化|
|O8（23→42）|0.678400|0.689664|−1.89%，未显示收益|

O3的cold配对区间`[0.98920,1.01144]`覆盖1，因此不宣称cold加速。
两列median略降而配对速度比略低并不矛盾：它们是不同的统计汇总。
O7/O8的cold区间分别为`[0.96034,1.01314]`、`[0.97126,1.00000]`，均不支持cold加速。

## 4. Steady-state：缓存权重后的在线执行

权重转换及重排提前完成；在线激活转换/重排和GEMM仍计时。

|后端|上一版最佳 median ms|新候选 median ms|配对吞吐变化|
|---|---:|---:|---:|
|O3（22→41）|0.611328|0.592896|+3.83%|
|O7（23→42）|0.629760|0.629760|−0.53%，无明确变化|
|O8（23→42）|0.635904|0.638976|−0.16%，无明确变化|

O3的配对区间为`[1.01730,1.04930]`；O7/O8区间覆盖1，未确认steady-state收益。
因此41/42是当前**GEMM最佳候选**，不是三种后端全部模式的统一最佳，更不应直接全局替换默认。

下面是各输出矩阵相对组内FP16参考的MSE，不是权重MSE或模型任务精度。

|---|---|---:|---:|

|O7|O5|0.005536172427|0.005053635834|

## 6. 改善原因与下一步

O7同binary的NCU对照如下；NCU时间只作诊断，不替代上述CUDA Event延迟。

|指标|旧23|新42|
|---|---:|---:|
|NCU Duration ms|0.467040|0.454816|
|Source shared wavefront|39,190,528|30,801,920|
|其中LDGSTS excessive|8,388,608|0|
|动态warp指令|116,252,672|117,547,008|
|寄存器/线程；最多CTA/SM|168；3|168；3|

输入排列改善了异步搬运，Source总shared wavefront减少21.40%。
但IMMA、I2F、scale乘法/FMA没有减少，动态总指令甚至略增，因此整体收益不是成倍加速。
理想容量模型下界仍约0.220347ms@1410MHz；它不是保证可达到的时间。

**转换直接写出G128-major布局已作为v25候选43/44实现**，省掉独立重排kernel。
GPU数值/安全检查通过，O3的24样本四模式已完成：43相对41转换吞吐+7.97%，
cold配对+0.70%但区间触及1，steady区间覆盖1，不能宣称端到端全面提升。
O7/O8全量也已完成：O7转换吞吐+7.54%，端到端尚无明确收益；O8转换−4.61%、
cold吞吐−2.21%。1152条四模式记录的输出全部逐位不变，不采用统一融合方案。
因此本报告上面的完整三后端性能表仍为v24，详见[v25结果](evidence/a100_o378_roof_v25/README.md)。
另已完成[N64四warp候选45/46](evidence/a100_o378_roof_v26/README.md)的A100验证：
寄存器降至126–128、零spill、最多4 CTA/SM，但24样本配对compute吞吐下降5.17%–9.12%，
全部输出/MSE逐位相同。因此不采用，也不把本轮不同频率下更低的对照时间拼入上表。
树形求和此前多版均未超过最佳，暂不继续盲目加大归约窗口。

随后完成[静态流水线槽位47/48](evidence/a100_o378_roof_v27/README.md)：
24样本中配对compute吞吐分别下降2.80%–5.64%和3.93%–4.70%，输出/MSE逐位相同。
NCU同stage对照显示，两阶段展开即使减少3.62%动态指令和61.72% local理论sectors，
eligible warp仍降低12.52%，性能反而退化；三阶段展开还增加了local访问。
因此不采纳47/48，当前最佳表不变。后续只针对关键依赖和供数做小范围优化，
不将“更少指令”“零spill”或“树更浅”单独当作收益证据。

[v28片段后处理排布49/50](evidence/a100_o378_roof_v28/README.md)也已完成：
将16个输出的I2F、scale计算和FMA分别成段，24样本未显示加速；49的O3基本持平，
其余配对吞吐下降0.79%–2.59%，输出/MSE逐位相同。NCU同stage的动态指令、
shared和local工作量均未减少，三阶段的eligible warp反而略降。
不采用49/50，上述最佳结果不变。后续不再仅重排同样数量的后处理指令。

## 验证与限制

576项合成数值/布局检查、原生INT4指令审计、有限memcheck/synccheck/racecheck通过。
12个旧正式kernel和114个旧候选的编码SASS未变。存在spill，已保留资源和NCU证据。
额外全SM80检查发现4个非本轮目标binary备选的FMUL操作数顺序/reuse提示变化，
不宣称整个扩展机器码不变；本轮目标对照未受影响，相关数值回归另行记录。
补充的480项binary GEMM等格式回归已通过；不将其作为O9/O10的新性能验收。
共享GPU、未锁频，不删离群或CV失败记录：五轮新最佳compute的CV≥3%数量分别为
48/120、44/120、33/120，**不等同于所有阶段均满足CV<3%的严格验收**。
24样本来自同一trace，bootstrap区间是描述性结果，不是24次独立模型实验。
