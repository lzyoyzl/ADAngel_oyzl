# O3 跨 G128 整数对齐：数据范围检查与两组候选

**状态：24样本范围检查已完成；用户已允许先测试两组候选，暂不改默认。**
这里只证明数据范围可行，不是新GEMM、MSE或性能结果。O7/O8不直接套用。

## 1. 为什么值得测试

当前O3每个输出有32次G128 partial→FP32转换及FMA。
权重scale是UE8M0，即2的整数幂；相邻两组可以用共同的整数单位精确表示：

```text
s0=2^e0，s1=2^e1，h=min(e0,e1)
Q=P0*2^(e0-h) + P1*2^(e1-h)
acc = fma(float(Q), 2^h, acc)
```

这不是把两个scale强行设成相同：两个原scale分别保留在移位量中。
量化、两路原生INT4和G128点积均不改变；A行scale沿用原54的最终epilogue。
区别是两次FP32累加改为一次，故允许合理的舍入差异，但必须重新验MSE。

每组最保守整数界为`P=128*128*8=131072`。
两组指数差d时，`abs(Q)<=P*(2^d+1)`；d≤13保证INT32不溢出，d≥14须回退。
实际实现不能对负有符号整数直接使用C++左移；采用有界乘法或明确的PTX位移。
UE8M0 code0是2^-127，不是零scale；code255必须拒绝。

## 3. 性能收益边界与风险

若两组均走安全路径，4096³的I2F/FFMA动态warp指令可分别由16,777,216降至8,388,608；
MMA仍为16,777,216，没有减少原生Tensor Core工作。
参考1410MHz时，I2F容量下界由0.220347ms降至0.110173ms，
但MMA下界仍0.220347ms。因此不能据此预测2倍加速，更不能宣称达到该下界。

新增代价包括：移位与整数合并、scale选择/guard、暂存第一组partial、两个G128的供数。
此前树形求和失败说明寄存器和片段复用可能抵消收益。本次先仅做两个G128，
保留N64窗口及B跨M复用；实测审计确认I2F减少之后，才判断性能是否值得保留。

需要验证：整数overflow guard及回退、独立scale、两路原生INT4、奇数group尾部、
finite FP32、24样本MSE、配对Event性能、spill/资源和内存同步安全。
转换/端到端仅在compute初筛有收益后晋级。原最佳和正式默认不受影响。

O7/O8涉及非二次幂的多级scale，不能用本次O3覆盖率或公式直接证明其可行。

后续获准的两组候选已完成v50：数值通过，但额外逐输出对齐/分支工作使性能退化，
没有采用。详见[v50实际GPU测试与NCU](evidence/a100_o378_roof_v50/README.md)。
下述范围检查自身仍只是CPU证据，不与后续GPU测试混为一谈。
