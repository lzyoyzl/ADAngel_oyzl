# v48：N方向寄存器流式片段宽度

状态：独立候选，尚未实测，不更改54/59、正式默认或5090。

## 根据与区别

当前最佳NCU仍显示MMA及整数partial后处理附近的等待。v47改变warp长宽比增加25% LDSM并退化。
本轮保持CTA64×128×128和2×2四warp，只改变一个warp一次保留多少B片段及独立INT32 partial。
v14曾在旧K256布局比较N32/N64，本轮是在G128-major、行scale后移/异步scale等当前最佳上重新隔离，
并加入完整N128片段，不能把旧结果或本轮预测当作当前实测。

|方案|流式N宽度|N片数|每次独立N MMA atom|每路INT32 partial元素/线程|
|---|---:|---:|---:|---:|
|0 原54/59|64|2|4|16|
|1|32|4|2|8|
|2|128|1|8|32|

全部保持64个FP32输出accumulator/线程、原M/N warp mapping、每G128两路INT4和K64两半。
N32可能降低live registers，但减少同时可调度的独立atom；N128相反，可能增加spill。
数学工作、理论fragment供数量不变；是否产生重复加载、寄存器分配或调度改善必须看SASS/NCU。
不进行magic、跨G128整数累加、FP32顺序改写或输入量化改变。

## 流程

1. CuTe主机检查每个N片的B坐标拼接严格等于原完整B坐标，两K64半均覆盖。
2. p0编码SASS与54/59相同，所有entry仍为原生U4/S4+S4/S4、cp.async.cg。
3. 180项有限数值检查、非默认stream、memcheck/synccheck/racecheck；不得以小形状安全检查冒充完整4096³覆盖。
4. 24真实样本×3轮，warmup50/repeats200，同Driver/Event交错顺序，不删离群/CV失败。
5. 输出与当前最佳逐位对照，重算O3/O0、O7/O5、O8/O6的FP64-reduced MSE。
6. 对候选与控制采NCU并核对实际指令/访存工作和PC等待；正向初筛再独立确认，负结果不晋级默认/端到端。

目标仍为缩小与现有kernel有效吞吐上界的差距。0.220347ms只是假设理想重叠的必要下界，不是保证能达到的时间。
