# v106：MXFP8 激活转换的 warp 寄存器查表候选

本轮只检查一个未测试的转换结构，不重复 tile、stage、warp 数、scale 缓存、
magic、树形求和或 v34 整数商/余数解码。GEMM 核心目标不变；此候选的收益即使
成立也只能归于 conversion/端到端，不能称为提高原生 INT4 GEMM 峰值。

现有 O7/v73 对16个激活逐个做 E4M3 解码、乘0.25和 RNE。新的128字节只读表将
128种正幅值编码的 Q8 结果打包为32个 word；warp 的每个 lane 通过一次 coalesced
只读 global load 持有一个 word。每个元素用 indexed shuffle 取 word、抽取 byte、
应用原符号。不是每个元素去访问 global/constant 查表，也不是 GEMM scale 查表。

F=−2、UE8M0有效 scale×4、低U4/高S4 packing、G128、平方和、factor/anchor、
整数范围与 FP32 安全 guard 均不变。权重仍使用原 v73；O8不改；两组使用同一个
原 v78 CUfunction。原库中的旧准备入口保留，并核对完整编码 SASS。

254个合法 E4M3FN 编码要求精确 RNE。127/255仍由既有源数据契约拒绝，表中保留
旧低层 decoder 的数值占位行为，不把它们当成合法 FP8 数值。

先进行 CPU 编码穷举及编译筛选：静态指令至少减少5%，寄存器不超过原32、
无 local/spill、shared=256B、一个 CTA barrier、16次 payload shuffle、旧编码不变。
这是潜力门槛，不是等同比例的延迟承诺。失败立即停止，不增加 GPU 性能/NCU。

通过后才做GPU全编码、现有 guard/stream/有限安全检查，随后直接24真实样本
配对测试 conversion、compute、Cold、steady及 MSE，不做小样本性能初筛。
计时保留双轨原实现：转换批量摊销，GEMM/端到端单次直接 CUDA Event。
所有原始波动保留；默认、正式扩展和5090不改。

源码须先本地提交并成功推送，再在A100项目内fetch/ff-only同步、编译：

shared=256B、一个barrier，寄存器未超过原32。不是19.72%的延迟提升。
## 完整实测结果与决定

**已完成。仅确认 O7 转换的小幅正收益，不更新 GEMM 最佳或正式默认。**
不继续扫查表/指令排列变体；它不是靠近 GEMM 有效吞吐上界的突破。

本地源码先推送，再在 A100 项目内同步：编译 commit 为 `b6b11631`，
运行 commit 为 `0f709ea8`。单独构建候选准备库，原生扩展未重编译；
两种 policy 绑定同一个 v78 GEMM CUfunction，CTA `64×128×128`、2-stage、
168 registers/thread、3 CTA/SM、local=0。O3/O8及5090实现不变。

24 个原始 FP16 trace 直接量化成原 O7 源格式，源量化不计时；完整 source identity
逐字段与 v99 相同。三轮交错 A/B，每轮 warmup=50、repeats=200、inner=100，
共576条四模式记录、345600个阶段 Event 值。未过滤离群值，不选最快轮次。

下表 ms 为每样本三轮 median 再跨24样本取 median；配对吞吐变化单独由
每个样本/同轮的旧延迟÷新延迟汇总，不是直接除两列跨样本 median。
bootstrap 按24个样本重采样10000次，seed=20261007。

| Steady：total | 0.525568 | 0.526848 | +0.19%，未确认 | 0.999990–1.003876 | 71/70 |

CV计数的分母均为72。Cold/steady里的 A 转换（仍为批量阶段计时）也分别有
+1.81%/+1.65%的配对吞吐变化；完整各阶段数据在 `analysis.json`。
Conversion-only total 是分别批量测得的 W/A 开销之和；Cold/steady total 是单次
执行的直接 Event 区间，不能混为同一计时口径。

转换总延迟配对下降约 **1.015%**；“+1.03%”指吞吐提升，不是下降百分比。
权重没有修改、无确认收益。两列 median 的细小 GEMM 差别不代表 GEMM 得到优化，
因为其 CUfunction 完全相同。采样时 SM clock 为1245–1410MHz，直接计时的较多
CV失败与频率变化/执行调度扰动相容；未做逐条归因，不能断言全部来自某个原因。
所有原始波动保留，**不宣称这轮端到端性能已达到稳定验收**。

由于转换总收益仅约0.7微秒，远小于约0.55ms的 Cold total，未确认端到端收益后，
不继续花费完整重测或 NCU 来追求该微小路线。这个决定不意味着最佳 GEMM 已达到目标。

## 正确性、MSE与审计边界

| 检查 | 结果 |
|---|---|
| GPU 精确解码 | 65536 个 thread/code 组合与原浮点解码及 CPU 参考一致；254个合法编码 |
| 合成输入/四模式/非默认 stream | 32项通过；9项非法编码/零/范围等 guard 检查通过 |
| 24样本四模式结果 | 576条 finite FP32；与 v67 全K参考逐位一致，最大差异和输出间MSE均为0 |
| O7 vs O5 输出 MSE median | **0.005536172273439442**，未改变 |
| O7 vs O5 输出 MSE mean | **0.005053635851002639**，未改变 |
| 新转换 entry 编译审计 | 静态指令568→456；regs32→31；shared256B、1 barrier、local/stack=0 |
| 原库入口 | 完整编码SASS一致；GEMM复用已审计的v78两路原生INT4 kernel |
| memcheck/synccheck | 新转换 entry 过滤、有限小M/N及K4096测试均为0 errors |

Sanitizer不是4096³、全部kernel或racecheck的完整验收；不扩大其结论。
静态指令减少19.72%远大于实测转换延迟变化，说明总转换还包含读取/写回、
packing、norm、factor/anchor和guard等未改变工作；新增shuffle也有代价。
未做本轮NCU，不能用静态指令数进一步断定具体管线占比。
