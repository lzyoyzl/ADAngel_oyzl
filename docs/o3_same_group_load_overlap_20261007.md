# O3 同 G128 的低位激活加载调度（v131）

## 动机与范围

目标是减少第一段 MMA 的供数等待，不改变计算工作量。
基准为当前最佳 O3 v89，64×128×128 CTA、4 warp、3 stage、32 个 partial 寄存器、全 K 精确 INT32 累加。
按实际 SASS 的寄存器读写追踪，4 条低位 A 的 LDSM 之前分别有 0、0、12、13 条 MMA（静态顺序，不是运行时发射测量）。
因此编译器**已经延后其中两条**，本轮只检查剩余提前加载是否还能调度到有用计算之后。

候选只拆开 `load_a`：先加载 high，在第一段 N64 的 high/high 点积之后、`high×16` 之前加载 low；后一段 N64 复用原 fragment。
原生 S4×S4 / U4×S4、G128 factor、guard、fallback、CTA 遍历、同步、最终 FP32 输出顺序不变。转换与正式默认不变。

已查重 v49/v94/v96/v97/v119/v128：不是跨 N 添加链、A 重载、去 volatile 或跨 K 交接；没有新 slot 状态、旧 factor 缓存或额外读写。
这只是一个有限的调度假设，不声称缩短等待必然带来吞吐提升。

## 在性能测试之前固定的门槛

- 完整旧控制编码不变；同一 entry 的 PTX/SASS 仍是两路原生 INT4 与异步搬运。
- 每 G128 仍为 32+32 MMA、16 LDSM、9 async copy、1 barrier。
- 静态循环最多增加 2%，allocated register 不超过 168、热 local 为 0、实际驻留至少 3 CTA。
- SASS 追踪确认所有低位 A 加载出现在至少 8 条 MMA 之后；静态未完成链峰值不低于 8。此计数不是硬件在途数。
- 通过编译门槛后才进行实际资源、安全与数值验证，再直接进行 24 样本三轮交错配对（1000 warmup / 200 repeats）。不做小规模性能筛选。

## A100 结果：机器码没有改变，停止该候选

源码 commit `212cde65ff6974e62fef956a29e04ba70dfccb48` 先推送 GitHub，再在 A100 项目目录同步编译；固定 CUDA 12.8 / CUTLASS commit 不变。

| 审计项 | 当前最佳 v89 | v131 |
|---|---:|---:|
| 每 G128 静态指令 | 323 | 323 |
| Allocated registers / thread | 168 | 168 |
| 热 local load / store | 0 / 0 | 0 / 0 |
| Signed / unsigned 原生 INT4 MMA | 32 / 32 | 32 / 32 |
| LDSM / async copy / CTA barrier | 16 / 9 / 1 | 16 / 9 / 1 |
| low-A 加载前的 MMA 序号 | 0、0、12、13 | 0、0、12、13 |
| 静态已开始未完成链峰值 | 8 | 8 |

不只是计数相同：去除符号名后，候选与控制完整 entry 的 **2200 条 SASS 指令机器字逐一相同**，机器字序列 SHA-256 均为 `510dcdfccc2f91ac37d7cffeef705bae3fae189afda1fde6f6e6c8750e9f5b47`。
源码改变未保留到实际指令调度中，未通过“低位加载确实延后”的预设门槛，因此不执行候选 GPU 或重复计时，也不继续扫描等价的源码排列。

这不是“实测提升 0%”：**没有新增 Event、MSE、CV、NCU、安全或端到端成绩**。已完成本地/A100源码测试；原始编译与回放证据见 [v131证据目录](evidence/a100_o378_roof_v131/README.md)。
当前最佳 O3 v89、O7/O8 v78 与正式默认保持，原有 MSE 结果不被改写。正式扩展 SHA 仍为 `94ad3751657474b6c895c32f824554b92951c0cbccd137a0f19d35bb51d7c462`。

## 对当前瓶颈和后续投入的含义

当前最佳已经预解码 scale 并异步搬运，且编译器已做部分 LDSM/MMA 交错。不能将这些已有手段再算作新优化，也不能把重排源码当作硬件流水线已经改变。
结合现有 NCU，仍需关注 **MMA→高低位重构→整数加权的依赖、供数/同步等待，以及寄存器对可驻留 warp 的限制**；并非恢复旧的逐组 FP32 FMA，也不是单纯增加 HBM 带宽即可解决。
后续候选须改变实际工作或依赖/资源组合；在机器码相同、供数翻倍或驻留下降时，不重复投入完整性能测试。

实现入口：[probe_o3_late_low_codegen.py](../scripts/probe_o3_late_low_codegen.py)。
平台可迁移性：延迟无关加载、缩短寄存器活跃区间是通用原则；具体加载顺序是否保留、MMA 依赖和资源收益必须在目标 GPU 的实际机器码中重新验证。
