# v21：独立乘积、树形求和与及时释放临时值（已测，不采用）

源码`21919b9`，A100/CUDA12.8；binary SHA-256：
`7a1f6cfd7621c6a3310dab2bcd3bbc94fbf2890a5555f30e5584bc9b564b63dc`。
完整文本证据归档SHA-256：`d03685218a41f1fb95a1a0c81bd93cea6ca957541c7b78c7e4a75d8ea369d87a`。
结论：数值回归通过，三个新候选均显著慢于22/23；不替换默认或最佳候选。

用户允许因计算顺序产生合理的 FP32 变化，本轮不要求新候选逐位等价。
仍不改定点转换、独立 G128 scale、原生双 INT4 及最终 FP32 输出；旧候选的
逐位门槛继续生效。所有新路径单 kernel、最终输出一次写回；没有额外全局 partial tensor。

|候选|方法|每输出理论上需保存的 FP32 中间值|
|---|---|---:|
|34|分别算完 4 个 rounded(P×S)，再相邻配对树形归约|4 个乘积＋跨窗口累加器|
|35|保存 32 个 rounded(P×S)，最后统一树形归约|32 个乘积＋累加器|
|36|与 34 同一四项树，算完一对就合并并复用临时值|一个叶子＋一个二项和＋累加器|

正式 K4096 有 32 个 G128，35 因此确实先算完全部乘积再统一相加，不是多条 FMA 链。
其他 K 的尾窗口补零；36 用显式尾部处理。34/35/36 都用 `__fmul_rn` 后接 `__fadd_rn`，
审计要求选定函数保留 FMUL/FADD，不能被编译器重新收缩为 FFMA。

CTA64×128×128、128线程、两阶段 cp.async、B fragment复用、升序 G128 点积不变。
launch-bound 放宽为 `(128,1)`，避免人为将新增 temporaries 限制在旧的168寄存器预算内。
实际寄存器/占用/local-memory 必须审计；源码中的线程私有数组不等于寄存器存储。
固定 4096³ 的临时乘积全量逻辑容量约为 32×4096²×4=2 GiB，不能预先假定没有代价。
36用于回答“及时合并能否减少这一存储代价”，而不是只测试容易变慢的完全物化方案。

三类实现的IMMA和I2F数量均为16,777,216条warp指令，没有减少实际点积工作。

**34/35：主要问题转成临时乘积存储。** `products[g][output]`保留整个输出tile的多个group，
最终产生大量LDL/STL，DRAM流量从约0.10GB增至4.02/10.59GB。
34即使ptxas显示无spill，也有1024B线程栈及实际local指令：显式线程私有数组本身就可能使用local memory，
不能把“零spill”误写为“全在寄存器”。本轮固定观测工作量模型最紧约束是DRAM带宽。

**36：缓解存储，但引入大量控制和计算指令。** 不再保存四个叶子，流量明显下降；
仍有255寄存器/线程和local访问，驻留上限低于22/23。`stage%4`的不同阶段分支出现在展开的
输出处理代码中，动态BRA约29.89M、FADD约33.42M，总指令为23的约2.34倍。
因此及时释放临时值有作用，但当前写法不是低开销的树形归约。
此时模型最紧约束变为总指令发射；不是继续宣称旧的0.220ms下界适用于新kernel。

这些下界只是假设理想重叠的必要资源约束，不是预测可达延迟，亦不是完整依赖链模型。
Local理论sectors和实际DRAM字节分别列出，不混为一谈。
