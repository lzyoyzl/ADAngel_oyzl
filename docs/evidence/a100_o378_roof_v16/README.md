## 改动和验收

24/25沿用候选6的64×128×256 CTA、256线程、两阶段cp.async、两路原生INT4及G128独立scale。
每个输出分别使用2/4个FP32累加器，按group模2/4分配，最后显式FADD树合并。
只在用户允许的独立重关联实验中运行；旧实现仍要求逐位一致。

- 69个候选实例同函数ISA审计通过；允许报告spill，不等于零spill。
- 12个旧正式实例、63个旧候选的编码SASS与v15相同。
- 288项合成数值检查通过；memcheck/synccheck各144项，0错误；有限K768 racecheck为0 hazards。
- 24样本×3后端×4实现×4轮，1152条compute-only记录；每种实现每个顺序位置24次。
  warmup=50、repeats=200；全部FP64语义容差、MSE回归通过，未过滤计时。
- 单真实样本四模式192条通过数值与计时接口烟测；它不是24样本四模式性能验收。

## 同一binary的O7 NCU诊断

`--set full --cache-control none --clock-control none`；每个候选只profile一次4096³。
NCU Duration是重放条件下的诊断值，不能替换上表CUDA Event时间。

|指标|对照6|两路24|四路25|
|---|---:|---:|---:|
|NCU Duration ms|0.486304|0.585952|0.985536|
|动态指令|127,238,144|137,019,392|168,574,976|
|local理论sectors|10,485,760|31,064,064|82,575,360|
|每scheduler eligible warp|0.887734|0.741340|0.419414|
|Issue active %|47.190240|42.527897|30.151265|
|L1TEX服务容量下界 ms @1410MHz|0.288044|0.339616|0.475234|

三者IMMA/I2F/FMUL/FFMA各为16,777,216条；shared工作量相同、excessive wavefront为0。
24/25额外FADD为524,288／1,572,864条。没有减少数学工作，主要改变依赖结构和活跃寄存器。
全部REG128预算下，O7两／四路stack为72／280 bytes，local流量约3.0／7.9倍。
not-issued采样中long-scoreboard占比由11.30%升至27.71%／57.26%；这是采样原因占比，不是耗时占比。

**结论：本配置下新增累加器的spill/调度代价超过收益，24/25不采纳。**
但不能据此证明所有并行求和都无效；下一步26/27只放宽寄存器预算，隔离spill与驻留warp的取舍。
更换工作量后重新计算上界；这里下界变差，不应继续用旧0.28ms当作新候选的可达时间承诺。
