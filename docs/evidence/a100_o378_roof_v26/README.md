# v26：N64 四 warp 候选——零 spill，但性能退步

结论：45/46不采用。24真实样本对照显示，两阶段45的吞吐下降5.17%–8.56%，
三阶段46下降8.77%–9.12%；新旧输出逐位相同，MSE不变。
GEMM最佳仍是O3/41、O7/42、O8/42，正式默认与RTX5090均不变。

## 实现与假设

目的：v24 的4-warp N128 GEMM实际使用168寄存器/线程，最多3 CTA/SM。
候选45/46将CTA改为`64×64×128`、WM2/WN2四warp，输出accumulator由64降为32/线程。
保持G128-major全局payload、B片段跨两个M atom复用、原有共享内存swizzle、
两路原生INT4、逐G128 scale和升序FP32 FMA；不改量化、不改求和、不使用magic-bias。

- 45/46分别使用2/3个`cp.async`stage，launch bound为128线程、4 CTA。
- 直接复用41/42的device body，独立TU只改变模板N和launch bound；旧实例保留。
- 不是重复旧9/10：后者为8 warp，WM4/WN2，没有当前跨M片段的B复用。
- 候选使用与41/42相同的**非融合**转换及payload重排，隔离GEMM实验。
  43/44转换融合不混入本轮，默认也不切换。

假设是减少寄存器和提高驻留CTA能改善延迟隐藏，**不是已经实现的性能收益**。
代价是N方向CTA翻倍，A载入重复次数、CTA同步/地址管理工作增加；即使零spill也可能更慢。

具体工作量预估：每个G128，原N128 CTA读A低/高共8KiB、W8KiB；新N64读A8KiB、
W4KiB，但CTA数量翻倍。因此全矩阵的payload搬运请求从16变成24个相同单位，增加50%。
这里是CTA请求量，缓存可能合并，**不等于DRAM实测增加50%**。数学MMA/I2F/FMA工作量不变。
目标驻留warp数从12到16（增加33%）也不等于性能增加33%；需要同时核对local访问、
shared wavefront、eligible warp与实测延迟，不能单凭occupancy判胜。

本地CUDA12.5独立TU编译通过：六个实例126–128寄存器、编译器报告零spill。
这不是A100 CUDA12.8结果，也不是GPU安全性或性能验收。132项CPU契约测试通过。

## 瓶颈与下一步

本轮证明：减少寄存器、消除spill、提高驻留都不是充分条件。减半N tile后，同一份A
要被更多CTA消费；原有两路INT4、逐G128转换/缩放工作量不减。

O7同binary的full NCU：`--set full --cache-control none --clock-control none`，
每个候选捕获预热后的一个目标kernel；raw/Source动态计数与PC采样均严格对账。
NCU Duration不是CUDA Event正式延迟，采集过程中的Event时间受重放干扰，不能用于性能表。

|指标|N128 / 42|N64 / 45|N64 / 46|
|---|---:|---:|---:|
|NCU Duration ms|0.452544|0.492672|0.498144|
|寄存器/线程；最多CTA/SM|168；3|128；4|126；4|
|实际occupancy %|17.96|24.18|24.18|
|Eligible warp/scheduler|0.7365|0.8364|0.8823|
|Issue active %|46.81|49.36|50.99|
|动态warp指令|117,547,008|131,973,120|137,723,904|
|LDSM指令|4,194,304|6,291,456|6,291,456|
|Source shared wavefront|30,801,920|44,564,480|44,564,480|
|Source local理论sectors|4,063,232|0|0|
|DRAM read / write MB（十进制）|22.23 / 69.39|19.00 / 67.56|18.68 / 67.66|

**核心证据：**驻留和可发射warp确实改善，但动态指令增加12.27%/17.16%，
LDSM增加50%，Source shared wavefront增加44.68%。三者IMMA/I2F/FMUL/FFMA
各为16,777,216条，数学工作没有减少；BAR与DEPBAR动态次数随CTA数翻倍。
即使去掉local访问，shared供数和控制成本仍抵消了资源收益。
DRAM流量没有增加，不能把这次退化解释成HBM带宽不足；Source中shared excessive
仍为0，也不能把增加的有效shared工作误说成新增bank冲突。

按相同1410MHz固定工作量容量模型，42的乐观下界为0.220347ms（MMA/I2F），
45/46约为0.259112/0.259032ms（L1/TEX数据服务约束）。这是必要容量约束的最大值，
不是可保证达到的kernel时间，也不能把各项下界相加。
N64甚至抬高了该模型下界，不能沿用旧kernel的有效上界评价新kernel。

未发射PC采样中barrier份额从8.49%升至18.33%/19.92%；wait份额反而降低。
这些是被采样等待原因的份额，不是总运行时间百分比，也不代表只要消除某条FMA链就能加速。

保留N128最佳对照，下一步优先减少不必要的供数/地址计算，同时保留跨输出片段复用；
不继续仅以更高occupancy或零spill为目标缩小tile，也不重启无收益的magic-bias实验。
树形求和此前的多版负结果继续保留，不能把缩短FMA依赖链单独当成加速证明。
