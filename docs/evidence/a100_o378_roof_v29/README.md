# v29：O3 行 scale 移至 epilogue——GEMM 配对吞吐提升4.28%

保持最佳41/42的CTA64×128×128、4 warp、G128-major输入、B fragment复用，
以及两/三阶段cp.async。仍使用两路原生INT4、每个G128自己的W scale、FP32跨组累加及输出。
O7/O8的A scale随G128变化，不能直接使用本优化，入口明确拒绝它们。

O3旧数学式：`sum_g(P_g * (A_scale[row] * W_scale[col,g]))`。
候选：`A_scale[row] * sum_g(P_g * W_scale[col,g])`。
G128顺序和每组INT32 partial不变，原UE8M0 scale没有合并或重新量化。
这在实数中相等，但改变FP32舍入，所以需要明确`--allow-reassociation`，
检查FP64语义参考、相对原实现误差，以及24样本对O0的MSE回归。

本地CUDA12.5独立编译和A100 CUDA12.8扩展编译通过，162项CPU回归通过。
源码`873ca2be992a52a0e972c7b57af0b201a230c87d`先推送GitHub，再经同提交bundle同步A100。
binary SHA-256：`cb59c3a0e3c6856eeda503bcce00bfbc06c1a539836d5d698206c2ea80711774`。

目标是减少循环内的scale组合和行scale寄存器活跃区间；**本候选没有减少I2F次数**。
旧O3已通过指数位运算合并scale，因此不能夸大为每组省掉一次浮点乘法。
候选每输出最后新增一次FP32乘法；实际调度、资源与性能必须测量。

新中间值尚未乘A_scale，可能比旧值大。两个host入口都显式检查
`max(W_scale) * K * 128 * 8 <= FP32_MAX`和最终结果保守上界，
并拒绝UE8M0 code0的subnormal W scale及非法code255；不满足时明确报错，
不偷偷改用另一个算法。普通正式后端仍保留原输入范围。

独立device header/TU；正式默认和RTX5090不变。51/52是显式允许FP32重新结合的内部候选。

- 192项GPU合成检查通过；memcheck/synccheck各84项检查，0 errors；K768 racecheck为0 hazards。
  这是有限测试，不是穷尽安全性证明。
- 20项GPU入口拒绝检查通过：prepared/four-mode两条路径拒绝subnormal W scale、code255、
  未缩放和最终结果保守上界溢出；prepared入口明确拒绝将51/52用于O7/O8。
- 140个候选实例通过同函数原生U4×S4/S4×S4和cp.async审计；新51/52均168寄存器，
  stack分别8B/16B，存在local指令。允许spill，**不是零spill验收**。
- 12个旧正式函数、138个旧候选的编码SASS不变。全SM80为265/270个旧函数不变，
  五个非目标mixed-binary函数发生FMUL操作数顺序/reuse提示变化，保留审计`passed=false`。
  补充mixed格式回归通过，包括480项binary GEMM；不作为O9/O10的新性能验收。

同binary O3合成4096³，`--set full --cache-control none --clock-control none`，
每函数捕获一次；NCU时间仅作诊断，不替代CUDA Event性能结果。

同stage的动态指令约减少11.44%/13.23%，local访问工作也减少。
四者的IMMA、I2F、FFMA仍各16,777,216条，LDSM为4,194,304条，
shared wavefront均29,622,272且无excessive；新候选只增加最终524,288条warp FMUL。
寄存器和理论驻留仍为168个/线程、3 CTA/SM。

**这是减少工作量带来的收益，不是所有利用率指标都上升。** eligible/issue指标下降，
不能据此否定实测加速；同时也不能把local理论sector当作实际HBM字节。
容量模型的必要下界仍为0.220347ms@1410MHz，受MMA/I2F约束；
本轮未减少二者，不宣称已经达到或保证能达到该理想下界。
