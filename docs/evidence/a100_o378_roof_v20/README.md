# v20：固定 4096³ 尺寸的独立候选（初筛不采纳）

源码 `58755de`，CUDA12.8二进制
`bc7ad35689446e7b421fd8e54ea561bf850c79a1775133399e3c7e5fff844755`。
归档SHA-256：`6e3273653eff5726ce726043174f950ea083ac775eafefd3ed4d81018b689e5e`。
以下已完成证据不包含24样本正式性能或NCU，不替代旧正式数据。

## 假设

v19 的 NCU 仍记录大量地址/索引指令；降低 spill 或改变 finish 顺序均未超过
当前最快的组合（O3 candidate22，O7/O8 candidate23）。本轮只把实验的固定
M=N=K=4096 传为编译期常量，让编译器简化步长、循环边界与地址计算。
不能预先宣称这种特化一定减少指令、减少 spill 或提高速度。

| 候选 | 对照 | 唯一源级改动 | CTA / pipeline |
|---|---|---|---|
| 32 | 22 | m/n/k 传入常量 4096 | 64×128×128 / 2 stages |
| 33 | 23 | m/n/k 传入常量 4096 | 64×128×128 / 3 stages |

二者使用原有 `o3_reuse_pipeline_candidate.cuh`，独立 CUDA 编译单元；
128 threads、bound3、原生 U4×S4/S4×S4、同样的 low+16×high 重构、
升序 G128 scale/FMA、原有转换及四模式计时不变。不存在新的 magic-bias
或 FP32 求和重排；所有结果要求与 production 逐位一致。

## 验收范围

- 准备后核心接口、O3 四模式接口、O7/O8 四模式接口均拒绝非 4096³ 输入，
  不伪装成任意 shape 支持、不静默回退。kernel 元数据标注 `compile_time_shape`。
- 4096³ 的随机、全零、极值、零 scale、二次幂及下溢模式逐位对照；
  非默认 CUDA stream；不以小尺寸测试代替固定尺寸正确性。
- 新旧 SASS 对照、原生 INT4/LDGSTS/流水线审计、资源和 spill 如实保留；
  memcheck/synccheck/racecheck 后再评价配对性能。
- 初筛固定 `-1,22,23,32,33`，五轮循序轮换，保留所有 CV 失败项。
  有收益再做 24 样本组内 MSE 与四模式复验。候选未通过前不改正式默认。

## 完成的验证

- 93个候选实例ISA审计通过（明确允许并记录spill），新6实例均为原生U4/S4和LDGSTS。
- 12个正式实例、87个旧候选的编码SASS完全不变；新实例均168寄存器，线程栈16–32B。
- 414项逐位检查通过，其中新候选36项全部使用4096³；42次非支持shape拒绝检查通过。
- memcheck、synccheck分别执行36项全尺寸数值检查，均0错误。没有进行v20 racecheck，
  也没有将继承旧同步代码的事实当成新的racecheck通过证据。
- 单真实样本四模式共36条全部逐位相同，确认转换/缓存/API语义；不是24样本性能验收。
