1. **编译期phase有效。** 37保持36数学顺序，却将BRA从29.89M降至0.53M，动态指令约减半。
   因而此前树形版本很慢，确有具体控制实现的问题，不是“树形求和天然慢”。
2. **两项窗口减少存储，但零spill不是充分条件。** O7的38无LDL/STL，仍占255寄存器、仅2CTA/SM，
   可发射warp少于23；O3的38仍有8/16B线程栈，不能把O7零local结论泛化到全部后端。
3. **没有减少核心点积和转换工作。** 各版本IMMA、I2F均16,777,216条warp指令，LDSM均4,194,304条。
   23为16.78M FMUL＋16.78M FFMA；38为33.55M FMUL＋16.78M FADD，动态总指令多约12.8%。
   分离乘法与加法缩短了单输出的跨组链，却增加实际指令；每线程原有64条不同输出的累加链也已提供并行度。
4. **本轮不是DRAM带宽问题。** O7/38实际DRAM流量约0.10GB，与23接近。剩余差距与更高寄存器需求、
   更低驻留/可发射warp以及额外指令相符，不能再简单归因于spill或全局显存流量。

资源下界是理想重叠的必要容量约束，不是可保证达到的kernel延迟；不能用0.220ms直接承诺下一版收益。
