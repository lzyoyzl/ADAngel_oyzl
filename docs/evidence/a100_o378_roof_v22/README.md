# v22：编译期phase与两项即时归约（待A100实测）

依据v21的NCU：候选36动态BRA约29.89M，总指令272.50M；虽然不再物化全部乘积，
仍受额外控制指令、255寄存器及local访问影响。本轮不修改正式默认或旧候选机器码。

|候选|改动|数值要求|
|---|---|---|
|37|与36相同四项树；4个phase模板展开，删除每输出运行时`stage%4`判断|必须与36逐位相同，再核对FP64语义参考和组内MSE|
|38|编译期2个phase；相邻两组乘积立即合并，只需一个leaf bank加acc|允许FP32重关联，仍须满足原有语义参考和逐样本MSE门槛|

两者CTA64×128×128、128线程、两阶段cp.async、双原生INT4、独立G128 scale、
单kernel、最终一次输出写回均不变。38缩短临时值生命周期，但每输出的跨窗口累加链较37长；
这不是“窗口越小一定越好”，必须测量。源码中未使用的pair tensor应由编译器消除，不能仅凭源码宣称无spill。

先进行独立编译和源码/CPU检查，再按本地提交→GitHub→A100 fetch/merge进行正式构建。
验证同函数INT4/异步搬运及无FFMA收缩，比较全部旧SASS；进行小尺寸/奇数G128/4096³数值与安全检查。
性能与旧默认、22/23及36同binary循环换序比较，保留CV失败；候选有改善才扩大性能验收。
无论正负结果均报告延迟、配对吞吐变化、MSE及是否采纳，不把本地CUDA12.5编译当作CUDA12.8 GPU验收。
