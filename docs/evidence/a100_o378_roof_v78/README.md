# v78：八条独立 INT4 累加链合并，真实 scale 配对测试

**结论：小幅改善，保留为独立候选，正式默认不变。** 24样本三轮GEMM约+0.89%/+0.89%；
另一次24样本四模式中Cold约+1.13%/+1.10%、steady约+1.00%/+1.16%，转换未变。
输出对v67逐位一致；大量直接计时CV失败保留，未通过严格稳定性门槛。

## 方法与不变项

仅测试 O7/O8 独立候选，不切换正式默认、不修改 O3 或 RTX 5090 后端。
保留 v67 的全 K 安全整数累加、各 G128 原始 scale、范围 guard / FP32 回退和最终 FP32 epilogue；
两条对照均使用相同 v73 GPU 在线准备。不是 v77 的单位 scale 诊断，也没有改变量化规则。

原实现每次处理一个 M atom，保留四个 N atom 的 low/high 两组 partial，形成八条独立链。
候选在 N64 slice 内同时处理两个 M atom，每个输出 atom 执行：

```text
partial = MMA(high_K0, W_K0)
partial = MMA(high_K1, W_K1, partial)
partial *= 16
partial = MMA(low_K0, W_K0, partial)
partial = MMA(low_K1, W_K1, partial)
acc += partial * A_factor[row,g] * W_factor[col,g]
```

每一步在八个 M/N atom 之间展开；仍为32个逻辑 partial 寄存器，不增加 A/B fragment 读取。
与 v63 的四链候选不同，保留八条独立链，但每条链增加 high→shift→low 的依赖。
G128 整数点积及最终整数和代数等价；乘16的中间值有界，源码不用负有符号整数左移。
CTA `64×128×128`、128线程、2-stage cp.async、34304B shared、N64流式片段不变。

所以不能把约1%的收益简单归因为“消除了8B spill”；也不能宣称必要MMA工作或容量下界降低。

## 对瓶颈的新增认识

这次保留八条独立链后，四样本负结果v63不能直接推广为所有high/low合并都无效；
但本次收益也只有约1%。MMA、LDSM、整数系数后处理和驻留容量没有实质减少，
并不是达到更高Tensor Core峰值的新算法。没有新增NCU，不从静态指令数推导具体stall时间比例。
目标仍是接近原有效吞吐上界，约0.220347ms的必要MMA容量下界没有改变；本轮仍未达到目标。
不继续围绕相邻调度顺序做无依据扫描；下一候选仍须证明能减少主要动态工作或改善实际供数/发射约束。
