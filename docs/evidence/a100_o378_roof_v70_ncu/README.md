# v70：当前 O7/O8 全 K GEMM 的剩余瓶颈

本轮是定向NCU诊断，**没有新增或切换GEMM，没有新的普通Event加速比**。
沿用v67的两份审计cubin、v69的GPU准备；对原最佳59与全K整数路径各采集O7/O8一次。
结论是：I2F已不是全K路径的主要容量约束，继续减少转换没有足够依据；
应关注新增整数运算与发射/依赖约束，而不是把静态spill报告当作当前执行热点。

## 方法与实测

A100 108 SM、CUDA12.8、NCU2025.1.1，真实`layer_00_q_proj`、4096³。
`--set full --cache-control all --clock-control none`，各独立进程，50次预热后只捕获一次匹配入口。
源码/二进制SHA、静态SASS指纹、grid2048、128线程和动态运算数量均核对。
每个被测输入2048个CTA全部通过整数guard；不是混入回退路径后的平均。

整数路径I2F减少96.875%，但IMAD约增至2.89倍，总warp指令只减少约10.42%。
IMAD既包含系数/整数重建，也包含地址运算，不能把4110万条全部算作scale乘法。
可发射warp仍低于1，发射率并没有随指令减少而提高。

全K入口的编译资源仍为168 registers/thread、8 B spill、3 CTA/SM，
但本次整数路径`LDL/STL`动态执行数为0；spill位于未执行的回退代码。
因此“把这8 B spill去掉”不是对本次热点的充分优化依据。
该结论只覆盖全整数路径，**不推广到O8实际存在的12个回退CTA**。

O7的Source口径shared wavefronts由31,285,248变为30,990,528，O8近似相同，变化很小；
excessive shared wavefronts由200,704变为0。两版LDSM均为4,194,304条，
LDS均为3,907,584条：主供数工作没有因全K累加而消失。
这些是指令/理论访问工作计数，不等于实际DRAM字节数或耗时比例。

各PC与总采样已对账。这些百分比是等待采样的构成，不是耗时占比；
PC指向等待的消费者，不能仅凭位置认定是哪条先前指令导致等待。
证据支持“缩放工作转移到整数域后，数学/依赖与有限可发射warp仍重要”，
不证明全部剩余差距都来自IMAD，也不能宣称消除某类等待就能获得同比加速。

按同一1410MHz容量模型复算，O7（O8近似相同）：

|必要容量下界 ms|原59|全K|
|---|---:|---:|
|两路INT4 MMA|0.220347|0.220347|
|I2F|0.220347|0.006886|

这些约束允许重叠，不能相加；0.220347ms不是保证可达到的时间。
减少I2F没有减少必要MMA，当前仍需改善整数工作、供数和调度的重叠。
NCU诊断耗时不可与普通Event表拼接成新的配对性能结果。

## 下一项值得测试的差异

先仅针对O7：它的UE8M0激活因子必定为`2^d`，可评估把
`partial * (A_factor * W_factor)`精确改写为`(partial * W_factor) << d`。
保留原整数范围证明，移位用无符号位模式避免负数左移未定义行为；
先检查是否确实减少IMAD、有没有新增每输出的FLO/寻址/寄存器压力，再决定GPU初筛。
这可能转移而不是消除工作，因此只作一个独立候选，不能预告收益。

O8激活scale含尾数，不能无条件套用幂二特化；O3可参考同类思路，
但其最新供数实现不同，应单独核对，不能把本次O7/O8数据当作O3测试。
不再次扫描tile/warp/cache参数，不重启magic，也不改量化或两路原生INT4要求。
