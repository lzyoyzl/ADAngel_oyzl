## 实现与验收

20/21保持CTA64×128×256、两级cp.async、两路原生INT4、G128与FP32 FMA顺序。warp布局由4×2改为2×2，每warp计算M32，在两个M atom之间复用B寄存器片；20/21分别使用N32/N64流式片。每线程64个FP32 accumulator，实际REG254–255、2CTA/SM，仅8warp/SM。

- 57实例ISA审计通过：同函数包含LDGSTS、U4×S4和S4×S4；允许spill但不豁免ISA。存在LDL/STL，不宣称零spill。
- 原正式实例12个、旧候选51个编码SASS全部保持一致。
- 288项合成逐位正确性检查；memcheck与synccheck各144项、0 errors；K768 racecheck为0 hazards/errors/warnings。安全检查范围有限，不是全shape证明。
- 单真实样本四模式48条全部逐位相同；不是24样本端到端结论。
- 24真实样本compute-only O7/O8共768条均与旧实现逐位相同，MSE未变。

## NCU解释：供数减少，但延迟隐藏变差

合成输入、同一二进制、同一kernel过滤；不是上述Event轮次。

两种后端IMMA/I2F/FFMA各保持16,777,216条。额外shared wavefront均0。复用使LDSM工作下降1/3，local请求也下降，但驻留warp和发射率同时下降：**减少访存工作不是充分条件，还需要足够独立工作隐藏延迟。**

用`af1cd54`中的分析器重新核算全部资源约束，结果见`resource_model_o3.json`、`resource_model_o7.json`。21的最紧容量约束已经变为MMA与I2F并列，约0.220347ms；L1TEX不再最紧。该值依然忽略依赖延迟，不是可达时间承诺，也不能把新实现描述成已经接近峰值。原约0.28ms模型仍对应旧工作量，不能不加区分地沿用。

后续22/23将复用与K128流水结合，测试两/三阶段及三CTA寄存器预算，检查能否在保留供数收益时提高可驻留warp；可能增加copy、同步或spill，必须审计和实测。当前不切换默认。
