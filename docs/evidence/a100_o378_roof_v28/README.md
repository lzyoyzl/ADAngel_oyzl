# v28：片段内转换 / scale / FMA 分阶段排布（49/50，待验收）

保持当前最佳41/42的CTA64×128×128、4 warp、2/3-stage流水线、G128-major输入、
B fragment跨M复用、两路原生INT4、逐G128 scale和升序FP32累加。正式默认和5090不变。

本轮不展开整个stage，不更改数学求和，不重启magic-bias。
只把同一片段内16个独立输出的后处理由逐元素`partial→I2F→scale→FMA`，
改成三段：先16个I2F，再原scale计算，最后原FMA。
这些临时值只属于一个G128和一个M/N片段；不是先保存32组乘积再归约。
`__fmul_rn`和`__fmaf_rn`不变，期望逐位一致，仍须GPU验证。

依据：v27对照显示指令少不等于更快，最佳版本的SASS存在I2F/scale到FMA的短依赖。
尝试改变编译调度，不能承诺一定隐藏延迟。NCU中的循环退出CALL也不能直接算作每组真实函数调用开销。
新片段数组可能增加活跃寄存器、spill或被编译器重新排回原顺序，必须检查资源和SASS。

独立TU/device header保留旧实现；CPU契约核对除了后处理块之外的源码完全一致。
验证计划：本地编译→GitHub→A100构建→旧代码保持与原生INT4审计→GPU数值/有限安全性→
4096³同进程换序初筛→24样本MSE/性能；有收益才做多轮与四模式晋级。
当前无A100结果，不计入最佳性能，所有负结果与CV失败保留。

本地CUDA12.5独立TU编译通过：六实例均168寄存器，16–32B stack/spill。
153项CPU契约/证据回归通过；这不是A100 CUDA12.8的资源或性能验收。
