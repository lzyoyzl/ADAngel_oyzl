# v27：静态环形流水线槽位——正确，但不加速

结论：47/48不采用。24真实样本中，两阶段47相对各后端当前最佳的吞吐下降
2.80%–5.64%，三阶段48下降3.93%–4.70%；输出与MSE逐位不变。
GEMM最佳仍是O3/41、O7/42、O8/42，正式默认与RTX5090不变。

## 实现

保持41/42的CTA `64×128×128`、4 warp、B fragment跨M复用、G128-major payload、
两路原生INT4、寄存器partial、独立G128 scale和升序FP32 FMA。
47/48分别为两/三阶段，launch bound仍为128线程、3 CTA，转换路径不变。

原循环运行时选择`slot = stage % stages`；候选展开2/3个物理槽位，
将槽位作为CuTe编译期整数传给同样的stage处理，三阶段预取的目标槽位也编译期确定。
这是地址/调度实验，不是split-K、树形求和或多累加链；没有合并数学scale。
G128按0→31顺序执行，尾部guard覆盖短/奇数组，wait_group、排空及CTA barrier保留。

目的：在不牺牲N128数据复用的前提下减少地址管理。
原取模可能已被编译器强度削减，因此不能把源码少一个`%`直接视作加速。
旧header保留，新TU隔离，源码契约比较payload/MMA/scale/FMA/barrier不变，
并模拟1–65组的槽位消费/覆写顺序。CPU模拟不替代GPU安全性检查。

## NCU：指令更少也可能更慢

O7同binary，`--set full --cache-control none --clock-control none`，各捕获一个预热后的
目标kernel。NCU时间仅用于诊断，采集过程中的CUDA Event受重放影响，不进入性能表。
两阶段41→47、三阶段42→48分别隔离了stage数量，不能只拿47和42推断槽位展开的效果。

|指标|两阶段41|静态两阶段47|三阶段42|静态三阶段48|
|---|---:|---:|---:|---:|
|NCU Duration ms|0.461440|0.480480|0.454624|0.475776|
|动态warp指令|118,390,784|114,106,368|117,547,008|118,497,280|
|Eligible warp/scheduler|0.7111|0.6221|0.7370|0.6741|
|Issue active %|45.75|41.92|46.88|44.68|
|Source local理论sectors|8,388,608|3,211,264|4,063,232|7,110,656|
|Source shared wavefront|30,801,920|30,801,920|30,801,920|30,801,920|

四者均168寄存器、最多3 CTA/SM，实际occupancy约17.9%；IMMA/I2F/FMUL/FFMA
各16,777,216条，LDSM各4,194,304条，shared excessive均为0。

两阶段展开减少3.62%总指令和61.72% local理论sectors，但eligible warp降低12.52%，
issue active也下降，实际更慢。三阶段总指令增加0.81%、local理论sectors增加75%，
eligible warp下降8.54%。这说明优化改变了编译调度和依赖暴露，不能只按指令总数或spill量判胜。
PC等待采样提供调度诊断，但不是总时间占比；没有据此证明唯一原因是某条FMA或指令缓存。
这里eligible表示已满足指令发射条件，而不是仅仅驻留在SM上；停顿样本定位的是等待的
consumer，需要结合前序SASS分析原因，不能直接归因给该PC指令。
口径参见[NVIDIA Nsight Compute Profiling Guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/)。

固定工作量容量模型下界仍约0.220347ms@1410MHz，约束项仍是MMA/I2F。
该模型不包含完整依赖与发射效率，不能据其不变就断言实际延迟也应不变。
下一步应保留原流水线与数据复用，只针对关键路径上的供数/地址生成做小范围改动，
避免进一步扩大完整stage或树形归约的展开窗口。
