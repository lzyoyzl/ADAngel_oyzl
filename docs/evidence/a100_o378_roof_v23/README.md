## 实现与假设

v22的两项树38在O7上已无local访问，但仍用255寄存器、最多2CTA/SM，慢于最佳23。
本轮改变G128/输出片段遍历顺序，只为小片段保存P0×S0，再马上计算并合并P1×S1。
不改变源格式、定点转换、G128独立scale或两路原生INT4；输出FP32、最终单次写回。

|候选|CTA / 线程|N片段宽度|每线程临时乘积数|流水线|寄存器预算|
|---|---|---:|---:|---|---|
|39|64×128×128 / 128|64|16|3槽G128，一次消费两组|launch bounds `(128,3)`|
|40|同上|32|8|同上|同上|

每次先让相邻两组就绪，空闲第三槽预取下一组；当前两组消费完成后执行CTA barrier，
才覆盖已释放槽。小M片段的两组A保留于寄存器，跨N片段复用；B需在不同M片段之间重新加载。
因此减少临时乘积是明确的，额外B加载/片段调度代价也必须测量，不能预设一定加速。

数学上严格保持38的二项树：先各自RNE乘法，再相邻二项相加，最后累加到输出。
39/40除通过原FP64参考及24样本MSE门槛外，还要求与38逐位相同；奇数G128尾组只加一次。
同binary保留旧默认、22/23及38作对照，不修改正式默认或5090代码。

1. **寄存器优化本身有效，但代价更大。** 39/40恢复3CTA/SM，O7无local访问；然而B fragment
   不再跨两个M片段复用，LDSM增加50%。算术后处理、地址/循环等工作使总动态指令比23多24.2%/25.7%。
2. **点积工作没有减少。** 所有版本IMMA和I2F均16,777,216条warp指令。23用一次FMUL构造scale、
   一次FFMA完成每项贡献；树形版本有两次FMUL及单独FADD。因此消除一条累加依赖不等于减少工作。
3. **零spill和更高occupancy仍不是足够条件。** 39/40可发射warp和issue虽好于38，仍低于23；
   更高指令/共享内存工作量使新增并行度不足以弥补。O7零local结论不能泛化：O3/39仍有8B线程栈和LDL/STL。
4. **不是大规模DRAM流量造成的退化。** 四个profile实际DRAM流量均约0.10GB。
   对39/40重新计算容量模型后，最紧的已建模约束转为L1/TEX数据服务容量；不能继续套用原0.220ms下界。
   这些下界假设理想重叠，不能相加，也不保证可达到。

PC未发射采样中，short-scoreboard占比23/38/39/40分别约7.7%/9.8%/17.5%/20.9%；
与更多shared→register加载及消费者等待相符，但这只是采样线索，不是时间占比或唯一因果证明。
所有版本Source标出的8,388,608个额外shared wavefront仍来自LDGSTS，不能误称为LDSM bank冲突。

## 决定与下一步

**不采用39/40，保留当前最佳22/23。** 树形路径已经测试多种窗口、编译期phase与小片段，
在当前CTA/算术下都没有超过最佳，下一轮不再仅靠缩小窗口试探。
优先回到最佳路径，检查cp.async的lane/地址映射所带来的额外shared工作，
并保持B fragment复用；随后才测试不增加加载量的调度调整。
先证明动态工作量减少，再做相同数值、安全与24样本配对验收；不承诺达到理想容量下界。
