# O3/O7/O8：真实累加器与供数容量诊断（v110）

结论：**没有新增正式 GEMM 加速结果，当前最佳不变。** 本轮完成了一项此前未做的容量诊断，
没有重复 tile、stage、cache、partial 存储或链数扫描。两个合格诊断 kernel 已完成运行；
带 scale 的第三个 kernel 因热循环 spill 未通过门槛，停止，不补造数据。

## 1. 与已有测试的区别

v82/v102 已测过 MMA 发射容量，但没有同时保留当前实现的 **64 个输出整数 accumulator、
32 个 partial、真实 CuTe fragment 布局和 recurring LDSM**。这次补齐这些必要工作，
不是重新测一遍单条 INT4 指令吞吐，也不是一个生产优化候选。

三个诊断均从冻结的 v78 八链源码生成，保留两路原生 S4×S4/U4×S4、G128 内
`high → high → ×16 → low → low` 合并及最终输出 owner。旧控制 entry 的 SASS 机器码相同。

|路径|G128 热循环保留的工作|状态|
|---|---|---|
|寄存器供数|64 MMA、两路合并、64 个输出整数累加；操作数在循环前读入|运行通过|
|shared 供数|上述工作，加上真实布局的 16 条 LDSM|运行通过|
|shared＋scale|上述工作，加上 32 组行/列 factor 读取及乘累加|编译门槛失败，未运行|

这里 shared 输入一次初始化后只读；**没有真实 kernel 的逐组 global→shared 搬运、
槽位复用、guard 与 pipeline 等待**。因此是受控供数诊断，不是完整 GEMM。

## 2. 方法与结果

A100-PCIE-40GB、CUDA 12.8、固定 CUTLASS；不锁频，不等待 GPU 空闲。
固定 2048 CTA、128 threads/CTA、输出 tile 64×128，预留 50688 B shared，
CUDA 查询两条运行路径均为 **3 CTA/SM**。输入为有符号、正负及零的合成周期模式。

每次 kernel 执行 **256 个 G128**，不是正式的 32 组：用较长热循环摊薄初始化和写回，
计时仍包含两者。下表除以 8 的列仅按数学工作量归一化，**不是实测 4096³ 延迟，
不是完整 kernel 的理论 peak，也不能作为新的性能最佳或与历史延迟做配对加速**。

每轮预热 50 次，两个路径交错执行、各测 200 次，连续三轮；全部原始 Event 值保留。

|诊断路径|256 组延迟 median ms¹|归一化至 32 组 ms¹|三轮 CV 范围|寄存器 / 驻留 CTA|
|---|---:|---:|---:|---:|
|寄存器供数|2.344960|0.293120|1.17%–2.03%|166 / 3|
|shared 供数|2.364416|0.295552|1.14%–2.00%|165 / 3|

¹ 每轮先取 200 次中位数，再取三轮中位数。归一化结果仍含摊销后的初始化/输出。
六组 CV 均低于 3%；运行前后频率快照均为 1410 MHz，不据两个快照声称全程频率恒定。

计时前进行 2 个 seed × 3 种组数（1/32/256）× 2 条路径，共 **12 次全输出逐位校验**；
每轮后再校验两条路径。每次比较全部 4096×4096 FP32 输出与 CPU 精确整数参考，全部通过。
这只证明所测合成模式，不替代随机输入、真实 trace、内存安全或 24 样本 MSE 验收。

## 3. 对下一步优化的含义

两条诊断的延迟差为 **0.83%**。在这个只读 shared 场景，加入 LDSM 后没有显著变慢；
因此，**再重复“少读几个 LDSM/替换 shared load”的相邻变体，优先级较低**。
两条路径的寄存器活跃范围、调度和 prologue 也有差别，不能把 0.83% 精确解释为 LDSM 的独立成本。

即使去掉热循环的 global copy、同步和 scale，保留真实合并与输出整数累加后的诊断
也约为 0.293 ms，而不是纯 MMA 理想容量约 0.220 ms。
这支持“**两路 MMA 之外的整数合并/累加和寄存器依赖也不可忽略**”这一判断；
不是证明真实 kernel 最快只能到 0.293 ms，更不能据此相减得到某种 stall 的耗时占比。

当前真实 kernel 还承担 factor/metadata、双路供数、pipeline 等工作。带 scale 的诊断
未通过无热 spill 门槛，故不能给出 scale 的独立耗时；后续需要减少这些**必要工作本身**，
而非继续已被否定的 factor 缓存、查表、相邻 stage/tile 或更长依赖链变体。
任何新候选先按机制查重，并核对机器码是否真的减少工作，才投入完整 24 样本测试。
