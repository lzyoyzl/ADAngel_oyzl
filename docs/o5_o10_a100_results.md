# A100 O5–O10 分组实验结果

## 结论

已完成两组六后端的实现、24 个真实样本的四模式测试和输出 MSE 检查。
在本次共享、未锁频 A100 上，O7/O8 的 compute-only 配对中位加速比分别为 **1.177× / 1.203×**，
Cold 为 **1.194× / 1.258×**，Steady-state 为 **1.212× / 1.226×**。
这些是相对各自 O5/O6 的观测收益，不是独占 GPU 条件下的保证值。

O9/O10 的实现和数值验证通过，但未取得性能优势：compute-only 分别为 O5/O6 的
0.276× / 0.348× 速度。两条 Binary 路径分别与 O7/O8 **输出逐位一致**，不会增加
bitplane 拆分误差；相对 FP16 基线的误差主要来自已定义的转定点路径与不同累加路径。
部分阶段 CV≥3%，因此不能宣称所有记录均通过严格稳定性阈值；所有记录均保留。

## 测试条件与口径

来源：`docs/evidence/a100_o5_o10_final_v3/runs/a100_o5_o10_final_v3`；24 个真实样本，1 轮，warmup=50，repeats=200，转换 inner=100。
源码：`3a97ce219ac75be9a4f7cb9d81c6117611cbfb3f`；二进制 SHA256：`3186f84b7c35c1933389a7ccafc092324d82a162af2eb5a9ddd20b8e42d0e3a0`。

组 A：O5/O7/O9 共用 NVFP4-G128 权重和 MXFP8 E4M3-G128 激活；组 B：O6/O8/O10 共用 HiF4-G128 权重和实验 NV-style FP6 E2M3-G128 激活。
初始源量化在计时外。组内分别是 FP16、双 INT4、Binary 路径；FP32 输出。

硬件为 A100-PCIE-40GB；PyTorch 2.7.1+cu128、CUDA 12.8；固定 M=N=K=4096。
原始 trace 来自 Llama-2-7B 的 FP16 prefill，batch=1、4096 个有效 token，六层×四种 projection。
原始 FP16 从 5090 复制并校验，两个源格式族直接从这些 FP16 张量生成，不使用二次量化。

Median：先对同一记录的 200 次重复取中位数，再在同样本多轮间取中位数，最后在样本间取中位数。Mean：对重复/轮次/样本取均值。加速比按同样本同轮配对后汇总，不能用表中边际 median 相除替代。

## 实现、审计与性能解释

| 路径 | 当前实现与主要优化 | 指令证据 |
|---|---|---|
| O5/O6 | 源格式直接解码为 FP16；复用 O0 的 cuBLASLt 计划，预分配 workspace，FP32 累加/输出 | 实际执行的 `ampere_s16816gemm_fp16_128x128_ldg8_stages_32x5_tn` 含 `HMMA.16816.F32` |
| O7/O8 | 源解码/定点/packing 融合；两路 INT4，64×128×256 CTA；cp.async 双缓冲、寄存器 partial、group-major scale 合并读取、最终一次写回 | 同一正式函数包含 U4×S4、S4×S4 IMMA 和 LDGSTS，不由 INT8 代算 |
| O9/O10 | 源解码/定点/ballot 融合；真正 8×4 / 6×4 bitplane；相同 CTA，缓存 W fragment、两条整数重构链、独立 G128 缩放 | 同一正式函数包含 B1 AND/POPC BMMA 和 LDGSTS，不由 INT8 代算 |

O7/O8 减少了操作数存储/搬运宽度，原生 INT4 提供计算收益；但双路重构、双侧 G128 scale
和 FP32 后处理仍有代价，不能按 INT4 标称峰值预测四倍加速。选定 INT4 kernel 有少量
local-memory/spill（审计记录线程栈 32 bytes）；按已允许的标准保留，未掩盖为零 spill。

O9/O10 每个 m16n8/G128 片段需 32 / 24 次平面对计算，以及有符号加权重构；
双 INT4 同范围为两路各两次 K64 MMA。Binary 的指令数、fragment 操作和寄存器压力
超过低位宽带来的收益。NCU 首轮 O9 记录约 8.22 亿动态 warp 指令、12.49% occupancy、
2.27% DRAM throughput，支持检查指令/寄存器/shared 路径，而非把瓶颈归结为 DRAM 带宽。
NCU 与 Event 计时严格分开，具体诊断见 [性能分析](o3_o5_o6_performance_analysis.md)。

格式穷举、独立整数参考、非默认 stream、四模式输出一致性、PTX/SASS 和 memcheck/racecheck
证据见 [验收归档](evidence/a100_o5_o10_preflight_v3/README.md)。24 样本的原始计时、MSE、
provenance 和 GPU 状态见 [完整实验记录](evidence/a100_o5_o10_final_v3/README.md)。

测试中观察到其他 GPU 进程及连续时段的延迟上升；这能解释部分异常，不能确认每个离群点的唯一原因。
未锁频、未等待独占、未终止他人任务、未删除离群值，也未重测至通过。主文数据来自固定的一轮完整运行。
后续诊断/候选复测只单独归档，不替换此处对后端有利或不利的样本。

复现命令见 [实验协议](o5_o10_a100_protocol.md)，转换公式、物理存储与 tile 计算见
[实现工作流](mixed_precision_kernel_workflow.md)。本轮没有重新运行模型下游任务，也未改变 O0–O4 的默认后端。
